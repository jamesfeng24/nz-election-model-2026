# Stage 8 correction — historical source provenance contracts

Two early Stage8 CI runs ([35818752590](https://github.com/jamesfeng24/nz-election-model-2026/actions/runs/35818752590) and [35818975228](https://github.com/jamesfeng24/nz-election-model-2026/actions/runs/35818975228)) failed Stage6/7 deterministic tests because the first Stage8 acquisition checkpoint appended two unrelated Parliament records to `data/sources.json`. The code pinned the SHA-256 of the **entire** registry. The appended records changed no existing source record or raw file. Before changing the contracts, the restored local registry was compared byte-for-byte with merged main: 901 records, SHA-256 `909b18ce1ddaa1d41ce1e91d987c4b70ae5cc3f02d59812660fc72b21334fa3d`, exactly the old Stage6/7 contract hash.

Stage6 and Stage7 actually use 42 supporting Māori candidate source records, identified by the six already-pinned historical source plans (seven per election). `data/source-plans/stage6-7-supporting-candidate-sources.json` is an immutable full-record snapshot of precisely those 42 records from the audited registry. Each stage now pins that snapshot instead of the mutable whole-registry file. At build time a shared validator requires every pinned record to remain present and exactly equal in the live registry, checks unique required URLs/IDs, and hashes the required raw bytes against their recorded SHA-256. Extra unrelated registry records are accepted. Changed or deleted required records, duplicate required URLs, changed snapshot bytes and changed required raw bytes fail. The historical source plans and 42 raw candidate files remain separately pinned by the existing input contracts.

The only regenerated Stage6/7 artifacts are provenance metadata: both `input-contract.json` files, both `manifest.json` files and Stage6 `records.json.inputHashes`. Stage6 fitted values/backtests/sensitivity/selection are byte-identical to merged main; its `records.json` is identical after removing `inputHashes`. Stage7 references, occurrences, diagnostics, normalization sensitivity and selection are byte-identical to merged main. Stage5, historical election data, raw files, the shared registry and Stage8 numerical outputs remain unchanged. No coefficient or residual was refitted or reselected.

Regression tests exercise each stage with an unrelated appended source, altered/deleted required record and altered required raw file. The Stage6/7 deterministic checks and full configured tests must pass before this PR is considered ready. The Stage8 Parliament source records remain in a separate, locally validated Stage8 source plan so they do not change this shared historical registry.
